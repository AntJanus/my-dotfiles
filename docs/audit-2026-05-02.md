## Flagged Findings

1. **`CLAUDE.md` references `bootstrap.sh` (Ubuntu) — file does not exist.**
   `CLAUDE.md` lines 14, 32 describe `bootstrap.sh` as the "Ubuntu bootstrap (apt-based)" and instruct readers not to run it on macOS. The file was DELETED in commit `73ece6a` ("major refactor 2026") on 2026-03-09. Either restore an Ubuntu/Linux bootstrap or remove the doc reference. Recommendation: scrub the CLAUDE.md reference and document that Linux currently has no bootstrap script (manual `apt install stow && stow -t ~ common linux`).

2. **`linux/.config/i3/i3status.conf` is a 0-byte file shadowing the populated `linux/.i3status.conf`.**
   `i3status` reads `~/.i3status.conf` (or `~/.config/i3status/config`), not `~/.config/i3/i3status.conf`. The empty file in `i3/` is dead and can be deleted.

3. **`ZSH_THEME="bureau"` then plugin list includes a heavy bundle (`git extract git-extras docker docker-compose command-not-found zsh-syntax-highlighting nvm`).**
   Not stale, but note that `nvm` plugin + manual `NVM_DIR` sourcing at the bottom of `.zshrc` overlaps. Both end up loading nvm, which roughly doubles shell startup work. Out of audit scope (rule: no semantic config changes), flagged for future tuning.

4. **`node_modules/` exists on disk but is NOT tracked by git.**
   `git ls-files node_modules | wc -l` returns 0. Already excluded by `.gitignore`. Looks like a leftover from a one-off `npx`-style invocation in 2025. Item r_dot05 ("Clean up node_modules") is effectively already-done from the repo's perspective. Local directory can be deleted but no commit is required.

5. **`.gitattributes` is comment-only.**
   File contains a single commented-out line referencing the [mathiasbynens/dotfiles issue 149](https://github.com/mathiasbynens/dotfiles/issues/149) explaining why CRLF normalization is intentionally disabled. Functionally inert. Kept as a deliberate "do-not-add-text=auto-here" marker.

6. **Bootstrap currently has no `--dry-run` and no Linux path.**
   `bootstrap-macos.sh` is macOS-only (the name advertises it). The roadmap item r_dot03 calls for a "symlink-based setup script for quick provisioning on a new machine". The right shape is a top-level `bootstrap.sh` that detects platform, then either symlinks via stow on macOS/Linux or calls into `bootstrap-macos.sh` for the Homebrew firehose.

7. **No hardcoded `/Users/antonin` or `/home/antonin` paths anywhere in `common/`, `linux/`, `utils/`, or `bootstrap-macos.sh`.**
   Searched with `grep -rn "/Users/antonin\|/home/antonin"` — zero hits. Good.

## Consolidation Opportunities

After walking the tree:

- **No duplicate `.zshrc` / `.bashrc` forks.** Only one `.zshrc` exists (in `common/`). Nothing to merge.
- **No overlapping config files between `common/` and `linux/`.** `common/` is universal; `linux/` is i3-only. Clean separation.
- **One real consolidation: delete the 0-byte `linux/.config/i3/i3status.conf`** (finding 2 above). The populated stow target is `linux/.i3status.conf`.
- **`utils/power-menu/`** is a single 638-byte script. Could be folded into `linux/` since it's i3-specific, but keeping it under `utils/` is fine — it's invoked from outside stow as a utility. No move recommended.

Net: one tiny dead file to remove. Otherwise the repo is well-organized post-2026-03-09 refactor and does not need structural consolidation.
